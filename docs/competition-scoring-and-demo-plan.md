# 比赛重点、得分点与演示主线

## 结论

官方强调的安全架构不是唯一赛题目标，而是把 Agent 的 Skill 做成可信、可审计、可复用资产的技术抓手。项目仍必须首先证明功能真实可用；安全治理、NVIDIA 适配和严谨文档是在此基础上放大技术深度与完整度。

## 得分优先级

1. 实用性与创新性（25%）：赛题原文一键闭环、真实解决 RTL 设计与验证成本。
2. 技术深度（25%）：任务分解、契约冻结、EDA 工具反馈、自动修复、记忆/评测、Skill 安全边界。
3. 项目完整度（20%）：稳定 GUI、前后端、可复现部署、详细说明书、成功演示。
4. 平台适配（15%）：展示 NVIDIA 技术栈的真实作用；H100/NIM/NeMo 适配应有可运行证据。
5. 演示效果（10%）：现场输入真实题，清楚显示阶段、失败修复、PASS 与产物。
6. 技术文章（5%）：问题、依据、架构、实验、局限与复现方式完整。

## 现场必须证明的最短路径

输入“设计一个 66x66 乘法器”后，界面依次展示：自动规格与接口 -> RTL/TB -> Icarus 仿真 -> Yosys 综合 -> 必要时 repair -> PASS -> 最终交付说明书。任何预录视频都不能替代这条现场可复现路径。

## 视频结构

1. 功能介绍：一句话赛题一键生成完整交付包。
2. 架构/设计原理：冻结契约、双生成器、客观 EDA 裁决、有限修复、记忆和安全治理。
3. 文献/工程调研：VerilogEval、RTLLM、AutoChip、ChipNeMo、ChatEDA、Reflexion 与 NVIDIA NeMo Agent Toolkit。
4. 效果展示：66x66 乘法器首个基线，再展示至少一个带状态的复杂设计和一次自动修复。

## 当前不能夸大的部分

- Windows + StepFun 闭环跑通不等于已完成 H100/NVIDIA 平台适配。
- 单个 66x66 乘法器通过不等于 Agent 泛化可靠；需要留出集统计。
- 生成 RTL 不等于完成；仿真、综合、报告与复现清单缺一不可。
