# SiliconForge 参赛视频脚本（90 秒）

> 最终录制应在 H100 迁移和真实盲测完成后进行。本文件先冻结镜头逻辑，避免后期把视频剪成“功能列表”。

## 核心叙事

大模型可以写 RTL，但不能自己证明 RTL 正确。SiliconForge 用真实 EDA 工具做硬门禁，让错误进入自动修复循环，最终输出可审计的工程证据。

## 分镜

| 时间 | 画面 | 字幕/旁白 |
|---|---|---|
| 00–06s | 黑底芯片网格，SiliconForge 标识点亮 | “生成代码很容易，证明芯片逻辑正确很难。” |
| 06–16s | GUI 输入一个未见过的握手控制器需求 | “只给自然语言需求，不提供参考 RTL。” |
| 16–28s | 需求、接口契约、RTL、TB 节点依次点亮 | “Agent 将需求转化为可综合 RTL 与自检 Testbench。” |
| 28–41s | 第一次仿真出现红色 FAIL，展开真实日志 | “失败不会被包装成成功。EDA 工具拥有最终裁决权。” |
| 41–55s | 显示局部 diff，修复节点脉冲，再次回归 | “模型读取证据，只修复相关逻辑，并重新运行原测试。” |
| 55–66s | 仿真与综合转绿，Skill Card、安全扫描、摘要出现 | “结果、权限、产物摘要与修复历史全部可审计。” |
| 66–78s | 运行环境面板从 Windows/StepFun 切换到 Linux/2×H100 | “同一工程从 Windows 开发机无缝迁移到双 H100 服务器。” |
| 78–87s | 盲测仪表盘展示 Pass@1、修复后通过率、平均修复轮数 | “我们不展示一次偶然成功，而是展示可复现的评测结果。” |
| 87–90s | Logo + 一句话收尾 | “SiliconForge — every RTL claim, backed by evidence.” |

## 必须使用的真实素材

1. H100 服务器 `nvidia-smi` 与 GUI `/api/runtime` 的双卡识别结果。
2. 一个真实失败后修复成功的完整任务，不使用预设 RTL 冒充模型生成。
3. `benchmark_report.json` 的真实数字，不预先写死百分比。
4. 仿真日志、Yosys/Vivado 综合结果、RTL diff、Skill Card 与安全报告。

## 录制规范

- 16:9，建议 2560×1440 或 1920×1080，60 fps。
- 浏览器缩放固定为 100%，隐藏书签栏、通知和密钥配置。
- 鼠标轨迹平稳，镜头切换服务于因果链，不快速扫过大量文字。
- 关键 FAIL/PASS、修复 diff、H100 与评测数据至少停留 2 秒。
- 背景音乐不盖过旁白，输出一个无音乐版本便于赛方二次使用。
